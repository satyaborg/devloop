# Polish the generated PR description footer and link back to the spec
Rework `draft_pull_request_body` so the PR description ends with a `devloop.sh` credit, drops the latest-commit line, and links back to the source spec only when that spec is committed inside the repo.

```mermaid
flowchart LR
  Current["PR body: top 'Generated by devloop --create-pr', footer 'Latest commit: SHA'"] --> Change["draft_pull_request_body: drop both lines, add committed-spec backlink + devloop.sh footer"]
  Change --> Result["PR body: optional spec link (only if committed and in-repo) above 'Generated by devloop.sh' at the bottom"]
```

## Problem
The draft PR body that `devloop --create-pr` writes (`draft_pull_request_body`, `devloop:3709`) reads like an internal tool dump rather than a finished description. It opens with `Generated by \`devloop --create-pr\`.` (`devloop:3724`) — the raw invocation, not a brand — and ends with `Latest commit: $commit` (`devloop:3744`), a noisy line that duplicates what GitHub already shows in the PR's commit list. It also never points a reader back to the spec that drove the change, so anyone reviewing the PR has no in-description path to the intent it implements. The moment it hurts: opening a freshly created draft PR, seeing a bare command string at the top and a redundant SHA at the bottom, and having to leave the PR to find the spec that explains why the change exists.

## Outcome
The generated PR body ends with the literal footer `Generated by [devloop.sh](https://devloop.sh)` as its last block (below the `---`), carries no `Latest commit:` line, and no longer contains the `Generated by \`devloop --create-pr\`.` text. When (and only when) the source spec resolves to a path inside the repo and is committed at the PR head commit, a `Spec:` line sits just above the footer linking to that spec via an absolute `https://github.com/<owner>/<repo>/blob/<commit>/<relpath>` URL. Otherwise no spec link appears, and the body still leaks no absolute local filesystem path.

## Scope
- In: `devloop` runtime — `draft_pull_request_body` (`devloop:3709`); a new `pr_spec_backlink` helper; threading `source_repo` through `create_pull_request` (`devloop:3644`) → `ensure_pull_request` (`devloop:3777`) → `create_draft_pull_request` (`devloop:3748`) → `draft_pull_request_body`, plus passing `$SOURCE_REPO` at the call site (`devloop:2267`). Tests in `scripts/devloop_test.sh` (update the PR-body block at `:1785-1788`, add a direct unit test for the new helper). `README.md` only if a documented PR-body example changes.
- Out: the `spec-pr-backlink.md` sibling concern (writing the PR URL into the spec's `pr:` frontmatter — the opposite direction, no shared code); review-round and final-report comment bodies (`round_review_comment_body` and friends); the report renderer; any change to which files devloop commits; supporting specs that live outside the repo (those simply yield no link).

## Behavior
### Happy path
1. User runs `devloop --create-pr <spec>` where `<spec>` is a file tracked and committed inside the repo.
2. devloop commits the pass and builds the draft PR body.
3. `draft_pull_request_body` calls `pr_spec_backlink "$SOURCE_REPO" "$spec" "$FINAL_COMMIT"`, which computes the spec's repo-relative path, confirms it is committed at `$FINAL_COMMIT`, derives `<owner>/<repo>` via `gh repo view`, and returns `Spec: [<relpath>](https://github.com/<owner>/<repo>/blob/<FINAL_COMMIT>/<relpath>)`.
4. The body renders the `Problem`/`Outcome`/`Acceptance Criteria`/`Review Trail` sections, then `---`, then the `Spec:` line, then `Generated by [devloop.sh](https://devloop.sh)` as the final block. No `Latest commit:` line and no top-of-body `Generated by \`devloop --create-pr\`.` line appear.

### Edge cases
- Spec under `.devloop/specs/` and untracked (the default devloop flow, excluded from commits by `is_devloop_runtime_artifact_path`, `devloop:1856`/`:3528`): `cat-file -e "$commit:$relpath"` fails → no `Spec:` line; footer still renders.
- Spec path resolves outside the repo (e.g. `~/Projects/specs/foo.md`): not under `$SOURCE_REPO` → no `Spec:` line.
- `$spec` empty or file missing ("if available"): no `Spec:` line.
- `$commit` empty or not a real object: committed check fails → no `Spec:` line.
- `gh repo view` fails (no auth, no origin, mock failure flag): backlink derivation aborts → no `Spec:` line; the rest of the body is unaffected.
- Spec committed at an earlier commit than `$FINAL_COMMIT`: still present in the `$FINAL_COMMIT` tree (git snapshots are cumulative) → link renders, pinned to `$FINAL_COMMIT`.

## Acceptance criteria
1. The generated PR body's final content block (below the `---`) is the literal line `Generated by [devloop.sh](https://devloop.sh)`, and the string `devloop --create-pr` does not appear anywhere in the body.
2. The generated PR body contains no `Latest commit:` line and no bare commit-hash line sourced from it.
3. When the source spec is committed inside the repo at the PR head commit, the body contains a `Spec:` line whose link target is an absolute `https://github.com/<owner>/<repo>/blob/<commit>/<relpath>` URL using the spec's repo-relative path, positioned above the `Generated by` footer.
4. When the source spec is untracked/uncommitted, the body contains no `Spec:` line and no `blob/` URL.
5. When the source spec resolves to a path outside the repo, the body contains no `Spec:` line.
6. The generated PR body contains no absolute local filesystem path (the existing `/Users/` no-leak guard at `scripts/devloop_test.sh:1788` still passes).
7. `bash scripts/devloop_test.sh` passes, including the updated e2e PR-body assertions and a new direct unit test covering the committed, uncommitted, and outside-repo backlink cases.

## Constraints
- Must: emit the spec backlink only when the spec is both inside the repo and committed at `$commit`; render it as an absolute `…/blob/<commit>/<relpath>` URL (GitHub does not resolve relative links in PR descriptions — verified against GitHub docs and `github/markup#101`).
- Must: derive `<owner>/<repo>` with `gh repo view --json nameWithOwner -q .nameWithOwner` run in the repo (the test mock returns `satyaborg/devloop`; the test origin is a local path, so `git remote get-url origin` cannot yield a github.com URL). On any failure, omit the backlink rather than break the body.
- Must: compute the repo-relative path by prefix-stripping `$SOURCE_REPO` from the absolute spec path (portable; avoid GNU-only `realpath --relative-to`), and never emit an absolute local path into the body.
- Must: stay best-effort and non-fatal — a missing/failed backlink never aborts PR creation or changes the run status.
- Avoid: relative-path or bare-path spec links; new dependencies; removing the `$commit` parameter (reuse it as the blob ref).
- Existing convention: explicit-argument functions threaded like the current `commit` parameter; heredoc body builders; direct-call unit tests that source `devloop`.

## Notes
- `$spec` is the canonical source spec the user passed (absolute, via `absolute_existing_file`, `devloop:2096`); the worktree copy `$run_spec` (`$repo/.devloop/specs/$slug.md`, `devloop:2169`) is never committed (`is_devloop_runtime_artifact_path`), so it is not the backlink target. This is exactly why the "committed" gate exists: in the default flow the spec is uncommitted and no link appears; a link appears only when the user keeps the spec committed in the repo (the user's stated workflow — "devloop commits").
- `SOURCE_REPO` is set without `local` at `devloop:2113`, so it is a global the body builder could read directly; the spec still recommends threading it as an explicit `source_repo` argument to match the existing parameter style and keep `pr_spec_backlink` unit-testable without relying on globals. Worktrees share the object store with `$SOURCE_REPO`, so `$FINAL_COMMIT` (created on the worktree branch) is reachable from `$SOURCE_REPO` for the `cat-file -e` check.
- `$commit` is `$FINAL_COMMIT`, the PR head commit; a blob URL pinned to that SHA is a stable permalink to the spec as of the PR head. Drop the now-unused `commit="none"` display fallback (`devloop:3720`) since the commit is no longer rendered as text.
- Relationship to the sibling draft `2026-06-18-spec-pr-backlink.md`: that spec writes the opened PR URL into the spec's `pr:` frontmatter (spec → PR); this spec links the PR description back to the spec (PR → spec). Complementary, independent, no shared code path — they can ship in either order.
- Verified facts: a single `Generated by` occurrence (`devloop:3724`); a single `Latest commit` occurrence (`devloop:3744`) with two test assertions (`scripts/devloop_test.sh:1785-1786`); the mocked `gh repo view` prints `satyaborg/devloop` (`scripts/devloop_test.sh:1178`); GitHub relative links resolve in committed markdown files but not in PR/issue descriptions.
- Gaps: 0.
